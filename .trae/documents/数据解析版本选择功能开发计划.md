# 数据解析版本选择功能开发计划

## 需求理解

在数据解析页面的标题"数据解析"右侧增加版本下拉框（1.0 / 2.0），切换不同收码解析逻辑：
- **v1.0**：维持现有逻辑，24个按键，帧长24字节
- **v2.0**：26个按键，帧长25字节（按键字节从3字节增加到4字节，后续偏移依次+1）
- 版本选择保存到配置文件，默认2.0

## 帧格式对比

### v1.0（现有，24字节）
| 偏移 | 长度 | 描述 |
|------|------|------|
| 0    | 1    | 帧头 (0xAA) |
| 1    | 1    | 索引值 |
| 2-4  | 3    | 按键状态（24位） |
| 5-18 | 14   | ADC数据 |
| 19-21| 3    | LED状态（20位） |
| 22   | 1    | 校验和 |
| 23   | 1    | 帧尾 (0xBF) |

### v2.0（新增，25字节）
| 偏移 | 长度 | 描述 |
|------|------|------|
| 0    | 1    | 帧头 (0xAA) |
| 1    | 1    | 索引值 |
| 2-5  | 4    | 按键状态（32位，使用26位） |
| 6-19 | 14   | ADC数据 |
| 20-22| 3    | LED状态（20位） |
| 23   | 1    | 校验和 |
| 24   | 1    | 帧尾 (0xBF) |

## 实现步骤

### 1. Rust后端 - 配置结构体增加版本字段
**文件**: `src-tauri/src/config.rs`
- 在 `MatrixConfig` 结构体中增加 `protocol_version: String` 字段
- 在 `Default` 实现中设置默认值为 `"2.0"`
- `key_names` 默认长度改为26（兼容v2.0）

### 2. Rust后端 - 配置文件增加版本字段
**文件**: `src-tauri/config.json`
- 增加 `"protocol_version": "2.0"` 字段
- `key_names` 数组扩展为26个元素

### 3. Rust后端 - 解析数据结构支持26个按键
**文件**: `src-tauri/src/matrix.rs`
- `ParsedData.keys` 从 `[bool; 24]` 改为 `[bool; 26]`（v1.0时只使用前24个）
- `DataParser` 增加 `protocol_version` 字段，从config中读取
- `parse_data` 方法根据版本号选择不同的解析逻辑：
  - v1.0: 帧长24字节，按键3字节(offset 2-4)，ADC offset 5-18，LED offset 19-21，校验和 offset 22，帧尾 offset 23
  - v2.0: 帧长25字节，按键4字节(offset 2-5)，ADC offset 6-19，LED offset 20-22，校验和 offset 23，帧尾 offset 24
- `read_and_parse` 方法需要传入版本号或从config中获取

### 4. Rust后端 - 增加版本切换命令
**文件**: `src-tauri/src/lib.rs`
- 新增 `set_protocol_version` 命令，允许前端切换版本
- 切换版本时同步更新 `DataParser` 和 `MatrixConfig` 中的版本信息
- 修改 `read_and_parse_data` 命令，传入版本参数或从状态中获取

### 5. 前端 - 增加版本选择下拉框
**文件**: `src/App.jsx`
- 新增 `protocolVersion` 状态，默认从配置加载（"2.0"）
- 在数据解析页面的 `Card title={t('data.title')}` 右侧增加版本下拉框
- 版本切换时调用后端 `set_protocol_version` 命令
- `parsedData.keys` 状态改为26个元素
- `keyNames` 状态改为26个元素
- `renderKeys()` 根据版本号动态显示24或26个按键
- `renderRawData()` 中帧长度根据版本动态调整（v1.0: 24字节，v2.0: 25字节）
- `loadConfig` 中加载 `protocol_version` 字段
- `saveCustomNames` 中保存 `protocol_version` 字段

### 6. 前端 - 自定义名称页面适配
**文件**: `src/App.jsx`
- `renderCustomNames()` 中按键名称编辑区域根据版本号显示24或26个输入框

### 7. 国际化 - 增加版本相关翻译
**文件**: `src/locales/zh.json` 和 `src/locales/en.json`
- 增加 `data.protocolVersion`：协议版本 / Protocol Version
- 增加 `data.versionV1`：v1.0（24按键）/ v1.0 (24 Keys)
- 增加 `data.versionV2`：v2.0（26按键）/ v2.0 (26 Keys)

## 注意事项

1. v1.0版本时，`ParsedData.keys` 的第25、26位始终为false，前端只渲染前24个
2. 版本切换后需要重新连接串口才能生效，或实时切换解析逻辑
3. 配置文件中 `key_names` 统一保持26个元素，v1.0时只使用前24个
4. 校验和计算范围：从帧头到校验和前一字节的异或，v1.0是0-21共22字节，v2.0是0-22共23字节
